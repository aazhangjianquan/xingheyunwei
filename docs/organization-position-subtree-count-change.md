# 岗位人数按部门子树汇总修正

日期：2026-11-09。状态：统计修正已完成并部署到当前本地平台，回归与实际页面验收通过。

## 需求与当前行为

用户要求选中「研发中心」时，岗位人数包含整个子部门层级。当前 `organization.position_out` 只有来源部门由管理员查看时汇总全部引用；中间部门查看继承岗位时只统计当前任职部门，导致其下级已分配人员未计入。

「未关联权限模板」表示岗位没有附加系统角色，任职仅用于组织管理；成员原有直接角色和其他岗位权限继续有效。为便于理解，将空模板提示改为「仅组织任职，不额外授予系统权限」，不替成员自动授予任何角色。

## 修正范围与验收

- 当前岗位列表中的每个岗位，按选中部门及任意层级后代的实际岗位分配统计。同一人在多个下级引用同一岗位只计一次，不合并不同岗位定义，也不计入兄弟部门或来源部门其他分支的分配。
- 统一管理员和部门负责人的统计口径；显示直属人数和含下级去重总人数，叶子部门仍显示本部门人数。汇总只改变计数，不扩展负责人可见成员、任职分配范围或负责人任命。
- 目录批量查询、单部门岗位接口、部门保存响应以及关联待办和项目统计保持一致。数据、角色、项目关系、审批及组织层级不写入改变。
- 仅修改 `backend/app/organization.py` 和 `frontend/src/OrganizationManagement.vue`，补充现有岗位继承测试和隔离页面验证。不涉及表结构，无新增 SQL，不改上一项尚待确认的项目创建方案。

## 实现与验证计划

复用一次批量读取的层级与岗位分配，在内存中将分配沿祖先链累积到人员集合，并分别保留直属集合。目录不逐岗位执行后代查询；单条响应也按相同子树范围计算。增加深层部门、重复任职、兄弟分支排除、无权限模板及负责人范围回归，核对不同接口结果一致并验证查询数不随岗位增长。

运行组织、岗位继承、角色和启动性能回归，前端测试及构建；隔离浏览器检查研发中心与叶子部门计数、无模板说明、桌面和手机布局。部署到当前本地平台前保留数据库、实例密钥和旧镜像，部署后核对原数据摘要及实际统计。

## 决策与回退

按岗位 ID 和任职部门关系统计，避免直接相加各部门人数导致兼职重复，也避免把同名旧岗位静默合并。此修改为用户对已批准并部署的岗位继承功能直接给出的统计修正规则，不涉及新的授权或审批设计。

可同时回退 API 与前端镜像恢复旧显示，无需数据回滚或 SQL 操作。测试和部署结果完成后补充。

## 回归结果

后端组织、继承、角色与启动性能回归 61 项通过；前端 138 项通过，生产构建通过。新增回归验证中间层多个子部门任职、人员去重、来源部门兄弟分支排除、直属与总人数区分、待办和项目统计不重复，以及部门负责人仅看到汇总数、不获得下级成员管理权限。目录、单部门岗位接口和部门保存响应结果一致，岗位增加时 SQL 查询数保持批量。
