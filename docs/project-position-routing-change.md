# 项目岗位独立选人与审批执行衔接（v1.0.8）

2026-11-09。用户明确要求项目岗位改为下拉选已有成员，并确认：销售/售前历史任命同时迁入两个岗位；移除旧业务角色的选项与授权依赖，保留基础系统角色、部门岗位和成员任命；运维审批及回填按关联项目岗位取人。

## 现状与变更范围

变更前 ProjectManagement、项目 API、项目可见范围、流程解析和任务资格都叠加检查旧同名角色。移除部门岗位所带角色会被组织保护检查阻止，因为其会令当前或后续任务失效。线上地址为 http://101.126.67.61/，公开健康接口正常；本地没有张建全账号，不把本地数据当作线上实例。线上认证数据和服务器部署连接尚未取得。

改为独立项目岗位目录：销售、售前、项目经理、申请人、技术负责人、智能体开发、运维负责人、运维人员、测试人员；删除项目管理者和产品开发。所有项目岗位可下拉选择平台启用成员，支持多人和搜索；不要求旧业务角色。项目经理仍由系统管理员指定，项目经理只能维护其项目其他岗位。项目外成员不能因同名部门岗位取得项目权限。

第一审保留已确认的组织负责人/逐级管理员规则。后续运维负责人和运维回填采用关联项目的运维负责人、运维人员任命。排除申请人本人；无处理人或不足审批阈值时明确阻止提交，不能跳过审批。固定审批人只检查账号和显式任命，不依赖其无关旧角色；首审负责人任命仍严格校验。任命撤销或停用若损坏在途流程继续受保护。

旧项目销售/售前拆成两个任命；部门负责人项目岗位映射为技术负责人。旧管理者、产品开发等退出项目岗位目录；原记录在迁移记录中归档。部门岗位名称、继承、多部门关系和人员保持，移除旧预设业务权限选项。新项目创建同时落实此前已请求的去除所属部门，旧项目部门数据保留。

## 影响与兼容

主要影响：项目岗位模块/目录、flow_api、flow_engine、organization、main 项目可见与变更运维人员校验、提醒的执行人资格、ProjectManagement、FlowSteps、WorkflowEditor 和组织岗位编辑界面。相应集成/浏览器回归与数据库迁移文件同步。

新增 WorkflowNode.assignment_policy 用于明确记录旧在途节点升级后的资格规则，保留原 instance snapshot、node config、任务快照、已审批记录和旧发布版本。当前/未来节点及已完成资源的执行联系人建立兼容规则；项目资格取自现存项目任命，不依据旧任务快照恢复已撤销的关系。旧部门角色审批若没有明确组织负责人标记，按原节点已指定的人员继续；现行组织首审保持严格任命校验。旧全局流程明确指定唯一运维负责人或唯一回填人时，可为缺少对应项目岗位的项目补齐等价任命；多人时不猜测，需要管理员在项目中指定。旧业务角色清理前先建立兼容规则，迁移幂等。没有关联项目的老节点按原明确人员继续，不新增虚构项目。

历史资源实际执行人继续作为明确联系人接收结束提醒；新项目执行人的提醒资格随项目任命校验。历史交付凭据由申请人、管理员或关联项目运维人员读取，不再由全局旧运维角色授权。

风险与验证：跨项目授权、项目经理范围、成员目录字段最小化、在途阈值和撤权保护、资源提醒执行人员、迁移幂等/历史不变、销售拆分、手机下拉与项目保存。用隔离 SQLite、MySQL 8 和真实浏览器验证；部署前备份数据库/密钥并保留旧镜像。v1.0.8.sql 增加字段，首次新 API 启动在事务中完成数据迁移。
