# 知识库空间开放范围变更

日期：2026-11-10。状态：用户已确认方案与线上部署，已发布到 https://xh.agentspro.cn 并完成线上验收。原空间授权保留。

## 目标与验收

空间负责人可以在新建和空间设置中选择「所有人」「指定部门」「指定人员」。开放指平台内已登录且启用的账号可阅读，编辑权限继续由负责人单独授予。

- 所有人：全平台启用账号可发现空间并阅读文档与历史版本，无匿名公开访问。
- 指定部门：可多选有效部门；提供「包含下级部门」选项，默认开启，页面明确显示。按实时组织归属判断，一个人加入多个部门时命中任意一个即可访问。离开授权部门后，下次请求重新校验。
- 指定人员：可搜索并多选启用成员；复用现有空间成员及只读/编辑角色。
- 三种范围均允许保留现有明确授权的协作成员。部门/全员范围仅额外授予阅读权限；删除某人的直接授权时，如果其仍属于开放范围，界面提示仍可阅读，避免错误承诺「已失去访问权限」。
- 只有负责人能修改范围。个人知识库保持私有；既有共享空间迁移为「指定人员」，保留原成员，不自动扩大范围。
- 权限同时覆盖空间目录、文章列表、搜索、正文、版本和知识库审计过滤；收窄范围后旧链接重新请求必须校验，前端遇到拒绝清理当前展示内容并保留现有草稿恢复机制。

本次聚焦空间开放范围，沿用现有页面布局、文档编辑器、版本/自动保存、负责人转让、删除恢复规则及账号登录方式。

## 从代码确认的现状

1. `frontend/src/KnowledgeManagement.vue` 是空间创建、设置、成员管理与文档编辑入口；创建时固定显示「指定成员」。
2. `backend/app/knowledge.py` 的 `accessible_spaces()` 仅允许个人库负责人和共享库负责人/直接成员访问。
3. `space_role()` 区分 owner/editor/viewer；编辑成员只能修改自己的文档，负责人可维护全部文档。
4. 新建和修改接口使用 `SpaceIn`；`kind` 表示 personal/shared，不适合承担新的开放范围，不改变其含义。
5. `backend/app/models.py` 的 `WikiSpace` 尚无开放范围字段；`WikiSpaceMember` 已有人员授权及角色。
6. `backend/app/audit.py` 使用同一个 `accessible_spaces()` 过滤知识库日志，且保存空间配置快照，需同步覆盖新字段。
7. `backend/app/migrations.py` 负责增量兼容；SQL 安装、升级文件也需同步。
8. 组织模型支持多部门归属，授权应读取部门 ID 和实时成员关系，不能根据可变的部门名称判断。

## 具体设计与影响范围

保持个人/共享的 `kind`，为共享空间增加独立的 `access_scope`（members/departments/all）。部门模式增加关联表和 `include_subdepartments` 标志；人员继续复用 `WikiSpaceMember`，不拷贝部门成员名单。

创建和空间设置沿用当前弹窗，增加三张范围选项及部门/人员选择器。保存时一次提交范围和选项，失败保留输入；只有保存成功后刷新空间与文档。设置页显示当前范围摘要和部门层级说明；切换到全员开放时明确显示开放对象。成员管理继续配置编辑权限。

后端集中扩展 `accessible_spaces()` 与 `space_role()`，由所有读取入口复用；开放范围仅贡献 viewer，直接授权可贡献 editor，负责人优先。保存先校验全部部门与人员，再以同一事务写配置、关系与审计，避免部分更新。移除部门、成员停用、范围收窄和多部门归属均在新请求重新校验。

实际变更文件：

- `backend/app/knowledge.py`：请求校验、范围保存、统一权限与输出。
- `backend/app/models.py`、`backend/app/migrations.py`：新增范围字段与部门关联；保留原权限默认值。
- `backend/app/organization.py`：部门删除影响检查增加知识库授权引用，避免新增外键导致删除接口报错；只有解除引用后才允许删除。
- `backend/app/audit.py`：记录范围和部门修改，并继续复用可访问范围过滤。
- `frontend/src/KnowledgeManagement.vue`、必要的现有知识库样式：创建/设置选择范围与准确的成员移除提示，复用可用的选择组件。
- `backend/tests/test_wiki_spaces.py`、相关审计测试、`frontend/tests/wiki-spaces.test.mjs`：权限矩阵、兼容、错误交互和相邻功能回归。
- 数据库安装/升级 SQL 及部署镜像所用 SQL 副本、README、本文档：保持部署方式一致，记录回归与回滚步骤。

## 风险、验证与回滚

主要风险是范围意外扩大、只限制页面而遗漏接口、多部门/下级部门判断错误以及移除直接成员后仍有部门授权却显示错误提示。

验证包含：三类范围 × 负责人/编辑/只读/无权限/停用账号；直接 URL 与搜索/历史/审计；跨部门、下级部门开关、多部门、成员调动；更新失败原子性；个人库隔离；旧数据升级幂等；负责人转让、删除/恢复、自动保存和版本回归；真实桌面和手机界面检查。使用既有独立测试数据，不修改线上空间、不向成员发送测试通知。

现状基线已执行：`PYTHONPATH=backend .venv/bin/python -m unittest discover -s backend/tests -p 'test_wiki_spaces.py' -q`，14 项通过。本结果为实现前的原功能基线；新增范围验证见下节。

回滚：发布前备份数据库与镜像。新增字段/表可保留；回退旧权限模块会恢复仅负责人及直接成员可见，因此部门/全员的隐式阅读权限将收回，需在回滚说明中明确。若需完全恢复授权配置，使用发布前数据库备份，须评估发布后的新增内容，不能直接覆盖线上新数据。

## 决策记录

建议复用空间成员管理承担人员与编辑授权，用独立字段描述开放范围。部门授权动态计算，不批量写入人员名单，以支持组织调动后的权限收回。权限集中于现有后端入口，保持现有交互布局和文档功能。用户已回复「可以」确认方案，已据此实施。人员选择直接复用原成员关系，保留既有编辑角色；旧客户端省略新增字段时保留原范围与授权。
