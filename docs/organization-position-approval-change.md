# 岗位授权与统一部门首审（v1.0.7）

## 已确认需求

成员直接授权只保留基础与系统角色；业务能力由管理员配置岗位模板，部门负责人分配本部门岗位。四类申请从本人已加入的启用部门中选择本次申请部门；单一部门可自动选中，多部门必须明确选择，不增加默认审批部门。

首审固定为本部门负责人；申请人是本部门任一负责人时，直接从父部门开始。逐级查找最近一层有资格且启用的负责人，最后使用其他启用的系统管理员，始终排除申请人。用户已确认唯一管理员没有独立审批人时暂不补配，提交前提示配置，事务不生成空审批任务。

## 代码基线与影响预算

- `roles.py`、`organization.py`、`main.py`：成员直接业务授权、岗位可委派范围、旧直接权限迁移和撤权保护。
- `audit.py`：在创建和重提历史中保存本次申请部门；删除部门预检查包含四类申请的历史外键引用。
- `flow_engine.py`、`flow_api.py`：现有首审默认直属上级、管理员用项目部门；升级改为强制组织首审，新增发布版本，保留原版本、快照和后续执行/最终审批。
- `models.py`、`migrations.py`、四份 v1.0.7 SQL 和安装 schema：四类申请增加可空的申请部门外键，历史记录不猜测回填。
- 成员角色选择、四类提单表单、流程配置与预览：基础角色和岗位授权分离，申请部门选择，固定首审规则说明。

## 兼容与安全边界

现有直接业务授权迁移到成员已加入部门的等价岗位，保留原项目关系、历史负责人兼容记录、在途审批及 License 密钥访问边界。基础管理员权限不能通过岗位委派。无有效部门的异常历史授权保留并记录，避免升级静默丢权。后续执行岗位及 License 最终审批配置仍需有效，不能任意指定无资格人员或自审。

组织写入与提单/审批共用授权锁顺序，撤任、停用和岗位撤权不得新增不可处理的在途节点；管理员须先转交待办或完成在途审批。原来已失效的任务不阻止无关调整，仍保留管理员转交入口。
