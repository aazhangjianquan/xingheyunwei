# 部门成员界面简化

2026-11-06，按用户明确要求直接实施，沿用已应用的需求变更工作流。用户已经要求去掉额外的部门分类与审批配置，无需再次确认同一变更。

目标：成员只展示所属部门、岗位与明确任命的负责人，不再提供「主」或「默认审批部门」的标记、说明、切换项。加入其他部门保留原部门关系、岗位、任命、直接角色和项目关系。

代码基线：`App.vue`、`AccountSettings.vue`、`OrganizationManagement.vue` 的部门列表附加额外标记；`MemberOrganization.vue` 有额外说明、复选框，并禁止移出旧单部门字段指向的部门；`organization.py` 的移出接口也有相同阻断。去掉复选框后必须同步解除该阻断，避免留下无法操作的组织关系。

实施范围：以上四个界面、集中组织移出接口和相关回归。管理员可明确移出任一部门，仅撤销该部门的成员关系、岗位和任命。旧单部门字段仅作现有系统兼容；移出其关联部门时，维护为仍加入的部门之一，全部移出时清空，防止初始化重新补回已移除关系。既有申请审批规则、历史快照和项目关系不在本次改动范围，不增加新的审批配置。

验收：所有相关界面不再出现额外标记或设置；加入和维护一个部门不改变其他部门角色；管理员可移出任一部门及最后一个部门，重新初始化不会恢复已移除关系；普通成员和部门负责人不可移出他人；部门岗位删除与去重人数保留。

风险和回退：无表结构变更，无部署数据迁移。移出仍采用组织写锁、修订检查和同事务审计。部署前保留数据库、密钥和镜像并核对原数据；应用可回退镜像，已经由管理员明确移出的关系应按审计恢复，不能整库覆盖后续写入。

决策：直接去掉用户拒绝的概念，不替换名称或增加其他审批设置。保留旧字段以避免无关的审批与数据迁移；成员管理以多部门关系为准。
