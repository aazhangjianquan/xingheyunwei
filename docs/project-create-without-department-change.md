# 创建项目移除所属部门

日期：2026-11-09。状态：已实施，合并到 v1.0.8 项目岗位变更中验收。

## 目标与边界

创建项目时只填写项目名称、状态及岗位成员，不再选择所属部门；新项目不自动绑定创建者或项目经理的部门。

保留系统管理员创建项目、至少一名有效项目经理、项目成员资格检查和项目权限边界。历史项目归属、项目成员、在途审批及已发布流程版本不迁移、不重写。项目列表现有部门筛选继续用于历史项目，不扩大本次需求到整个项目管理页。

## 验收规则

1. 创建项目窗口没有「所属部门」字段，也不为创建项目请求加载部门目录；提交无需部门参数，项目名称、状态及项目成员可正常保存。
2. 新项目保存 `department_id=NULL`、`department=''`，不创建虚构部门，也不隐式绑定任何成员部门。其可见和管理范围继续按现有项目成员及角色判断，管理员保留全局权限。
3. 新项目后续维护仍无需选择部门。历史项目维护不再要求填写部门；更新请求省略部门时保留历史归属，旧客户端明确提交部门 ID 时仍校验真实、启用的组织部门。
4. 普通提单人仍按本人已有部门匹配部门审批。管理员提交无所属部门的新项目时同样按其本人已有部门匹配；历史有部门项目保留原有管理员按项目部门提交的行为。没有可用部门或合格负责人时沿用明确拒绝提示，不猜测其他成员的部门。
5. 不新增默认部门、默认审批部门等设置；现有项目经理必须配置、成员角色有效性和拒绝越权规则继续生效。

## 当前代码与影响面

- `frontend/src/ProjectManagement.vue`：创建与维护共用表单，管理员总会加载 `/organization/options`；新项目初始化空部门，表单必填，保存总提交 `department_id`。
- `backend/app/flow_api.py`：`ProjectIn.department_id` 为必填；创建和维护都调用 `require_department`，因而只去掉前端字段会返回 422。
- `backend/app/models.py`：`Project.department_id` 已可空，`department` 可保存空字符串，本次无需迁移或新增版本 SQL。
- `backend/app/flow_engine.py`：普通用户按提单人部门匹配审批；管理员始终使用项目部门。需仅为无部门项目增加提单人部门回退，避免新项目的管理员提单因缺少项目部门失败；不重写历史项目或流程。
- `backend/app/organization.py`：旧部门回填仅处理非空历史标签，空字符串项目不会被启动回填成创建人部门，无需修改。

代码改动限定为上述前端组件、项目 API 和流程部门解析；复用并补充 `frontend/tests/project-loading.test.mjs`、组织与流程测试及必要的隔离浏览器检查。模型、安装 SQL 和 v1.0.4/v1.0.5/v1.0.6 保持现有结构。

## 实现、验证与回退方案

创建表单删除部门选择；历史已绑定部门的项目维护也不显示部门字段，后端保留原归属；新项目保存为空。请求省略不适用的部门字段；后端区分省略与明确提交，保留历史数据兼容。审批来源仅对无部门项目回退到提单人的既有组织归属。

验证：无部门创建与后续维护成功、不能越权创建、缺项目经理拒绝、历史归属省略时保留、旧客户端部门参数校验、项目成员访问范围、普通与管理员的无部门项目审批、历史管理员项目审批及在途快照保持；前端请求不额外加载部门选项。运行相关回归、构建、真实浏览器检查桌面和手机创建窗口及正常保存。

批准后修改并部署到当前本地平台，部署前保留数据库、实例密钥及原镜像，升级后核对原项目、成员和审批数据。不新增 SQL。若回退，需保留支持无部门项目的后端或先关闭项目写入；已有无部门项目不能重新由旧前端要求填写部门来掩盖兼容问题，不自动补填或清理这些项目。

## 决策记录

建议让新项目独立于部门，成员权限由项目岗位管理，部门审批使用提单人的已有组织关系。没有采用隐藏字段并自动绑定管理员部门，因为管理员可能跨部门创建项目，隐藏绑定会改变项目归属且难以察觉。

无部门创建、跨部门任命、请求不加载部门目录和完整组织首审已通过后端及浏览器验收。本功能本身无需 SQL；本轮合并升级另需 v1.0.8.sql，见 [项目岗位验收](project-position-routing-change.md)。线上尚未修改。
