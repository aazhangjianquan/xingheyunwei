# 部门／岗位删除与默认审批部门说明

> 本文保留前次实施记录。用户已要求移除额外部门标记和审批设置，当前行为以 [部门成员界面简化](organization-simple-membership-change.md) 为准。

2026-11-06。按用户明确要求，补齐系统管理员删除部门、岗位的能力，并解释和替换含糊的「主」标记。沿用已应用的需求变更工作流，不再重复请求对本次明确变更的确认。

现状：组织页仅有创建、编辑和停用；后端无删除接口。成员部门显示「（主）」但缺少说明，实际用于确定普通成员的新申请默认审批归属，不表示负责人或权限高低。

方案：标记统一为「默认审批部门」，组织调整面板补充用途说明。管理员在所选部门及岗位卡片可点击删除，先查询删除影响并在弹窗确认。只删除已清空关联的部门和未分配成员的岗位；部门检查所有直属成员（含兼职／停用成员）、全部子部门、项目、岗位、负责人、待审批和现行流程引用。岗位成员须先明确解除，不随删除自动撤权。历史审批版本与业务记录不改写；删除空部门时同步清理无业务含义的名称别名，删除空岗位时清理权限模板关系。成功与阻断均由后端裁决，并记录删除审计。

权限与事务：GET 影响和 DELETE 均仅系统管理员可用；DELETE 入口先获取既有组织写锁、检查修订号和关联，拒绝陈旧确认、越权与只读维护。影响预览可过时，最终提交必须重新核验。前端仅打开和关闭线上确认弹窗，所有删除写验收均在隔离数据上执行。

验证范围：管理员成功删除空部门／空岗位；成员和负责人无权删除；所有关联阻断；别名与模板关系正确清理；失败不影响原数据；修订冲突、维护开关、重复删除和删除审计。回归既有多部门保留、人数汇总与审批规则。部署前备份数据库、密钥和镜像，摘要核对所有原业务与组织行不变；本次不需要新表或数据迁移。


## 实施、回归与决策

成员列表、组织页和个人资料中的「（主）」统一替换为「（默认审批部门）」；调整组织面板解释其用途，并把选择项改为「设为默认审批部门」。默认审批规则及多部门授权来源保持不变。

删除入口只向系统管理员展示。确认弹窗读取独立影响接口，显示最新名称、修订号和阻断项，成功删除后刷新目录与人数；被阻断或修订冲突时保留弹窗及错误信息，可重新检查。后端提交时重新加组织写锁和检查关联，防止仅凭旧预览删除已经被使用的配置。删除记录与审计记录同事务提交。

64 项相关后端用例全部通过，包括 7 项新增删除权限／清理／阻断／并发／维护测试。前端 133 项通过，Vue 生产构建成功；22 项隔离浏览器检查通过，覆盖完整标记、管理员确认删除、岗位关联阻断和负责人无删除入口。MySQL 8.4 实测未分配岗位删除后模板关系清理、空部门删除后别名清理、关联阻断，以及多部门及审批原规则兼容。结构同步和 diff 空白检查通过。

证据：`reports/organization-delete-backend-tests.log`、`organization-delete-frontend-tests.log`、`organization-delete-ui-tests.log`、`organization-delete-mysql-tests.log`、`organization-delete-build.log`；浏览器截图为 `reports/organization-delete-blocked.png`。

选择明确解除关联后再删除，不使用批量级联删除人员、子部门或岗位，也不改变历史审批版本。可通过移出部门、调整岗位、迁移项目／下级部门、更新现行审批引用后再次删除。应用发布本身不删除任何真实组织记录，也不修改现有权限。
