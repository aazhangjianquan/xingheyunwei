# 统一部门管理与上级负责人审批调整

> 最新规则已按用户后续要求调整为一人多部门，加入其他部门及切换主部门保留原岗位与任命。旧单一归属规则由 [多部门与人数调整](organization-multi-department-change.md) 取代。

日期：2026-11-06。用户明确要求删除旧职责卡片和四类负责人入口，统一从部门管理维护，并确认跨部门添加成员按调入处理；依此实施，无需重新确认原有明确指令。

## 需求与源码现状

- `App.vue` 仍渲染「部门与职责联动」卡片，角色目录仍暴露商业化／项目经理／技术／智能体开发负责人。旧角色还能直接授权与维护人员，和新组织管理重复。
- `OrganizationManagement.vue` 只有新建账号入口，负责人选项仅本部门；没有从全平台选择已有成员调入的入口。
- 工单按申请归属部门本级匹配部门负责人，变更／交付默认模板还从运维负责人开始。
- 当前平台已有真实部门层级和明确负责人，调整必须保留现有组织配置、原授权记录、项目关系、已发布版本和在途任务。

## 实施与验收范围

1. 移除旧卡片及四类负责人在新授权、岗位模板、流程和项目选项中的入口。组织人员管理权只来自管理员或明确部门负责人；旧直接授权留作历史记录，不再提供人员管理权。
2. 部门页提供「添加已有成员」与「新建成员」；管理员可搜索全平台已有成员并调入当前部门，分配岗位。使用组织修订号防止覆盖，保留直接角色和独立项目关系；原部门岗位及任命撤销前展示影响。
3. 新工单默认首节点使用直属上级部门负责人；顶级部门使用本部门负责人。仅匹配明确任命，不逐级猜测或借用旧职能角色；缺少负责人、本人自审或人数不足时明确提示。
4. 首节点原先为运维等业务审核的流程，在新版本前插入部门负责人节点，保留后续审核。升级只新增版本，不改旧版本、在途处理人或意见；管理员后续仍可配置流程。
5. 回归验证角色拒绝、历史任务兼容、跨部门调入与撤权、多级部门首节点、缺配置、自审与审批快照。用隔离数据验证写路径，部署后仅只读核对实际平台。

涉及 `roles.py`、`organization.py`、用户写接口、流程解析／初始化、组织及角色前端组件与对应测试。沿用一个成员一个所属部门、多岗位的模型，不新增多部门兼职。

## 风险与回退

旧负责人身份仅保留历史任务读取，不应继续变成人员管理权；新审批快照标明组织任命来源及实际匹配的上级部门。部门层级后续变化不改原快照。

部署前备份数据库、实例密钥与旧镜像；升级记录新发布的默认流程版本。需要停止调整时使用组织维护开关。回退保持兼容组织数据读取；已提交的新上级审批任务不得通过恢复整库或改写快照自动回退。


## 实施与验证

- 删除「部门与职责联动」整块界面；角色目录、成员角色选择、岗位权限模板和项目新分配不再提供四类职能负责人。通用部门负责人也只能从部门管理任命。旧直接授权仍保存，只用于兼容历史审批身份，不产生当前人员管理权。
- 「添加已有成员」从全平台账号选择，支持姓名、用户名和原部门搜索。调入采用组织修订号，保留原直接授权、密码与项目关系，撤销原部门岗位和负责人任命；部门负责人无跨部门调动入口及接口权限。
- 首个有效部门负责人审批默认匹配紧邻上级，根部门匹配自身；后续默认部门节点匹配本部门。匹配结果冻结实际审批部门 ID 与任命来源；缺少任命、停用和自审均有阻断提示。
- 四种业务发布新的默认流程版本，已有运维审核等后续步骤保留。旧版本、在途实例和任务不重写。管理员已编辑草稿不覆盖，未修改草稿同步新版本。首次初始化先刷新待落库版本，只有草稿的业务不误触发布。
- 旧 `WorkflowAssignment` 仅在尚无版本化流程时做首次导入，不再根据新负责人任命补建旧路由。

验证：`reports/organization-unified-backend-tests.log` 101 项，无失败（2 项真实 Java 条件跳过）；最终追加的初始化／草稿迁移用例及整理后相关 36 项全部通过，见 `reports/organization-unified-final-targeted.log`。前端 133 项全部通过，生产构建成功。隔离 SQLite 与构建前端的浏览器验收通过 13 项，涵盖旧入口消失、跨部门调入、原授权和项目关系保留、原岗位及任命撤销、负责人范围、普通成员和 390px 布局；见 `reports/organization-unified-ui-tests.log` 与 `reports/organization-ui-verification.json`。`git diff --check` 与部署结构同步检查通过。

## 决策记录

一个成员保留单一部门归属，以调入方式处理全平台已有成员，依据用户明确选择；跨部门兼职未加入本次模型。负责人仅由明确任命产生；父部门审批只影响审批匹配，不自动扩大人员管理范围。历史身份留在原记录，保障在途任务兼容；新增版本应用新规则，避免更改过去已发布配置和审批证据。

部署前按表核对原数据，六张组织表完整比较内容摘要；旧已发布流程版本逐行核对不变，只允许四种业务各新增一个版本。主密钥、账号密码、直接角色、项目关系和审批历史全部受一致性保护。备份及回退镜像保留于忽略目录 `reports/organization-backups/`。
