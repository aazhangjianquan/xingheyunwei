# 知识库保存与版本规则

编辑已有文档时，停止输入约 1 秒后自动同步内容，不增加界面中的版本号，也不写入历史版本。自动保存保留当前文档状态，有访问权限的成员可以看到已同步的内容。

点击“保存文档”并成功保存后，版本号增加 1，并记录这一刻的标题、分类、正文、状态、保存人和保存时间。即使内容已自动保存，点击该按钮也会生成一个版本。新文档首次保存为 v1。

保存进行中按钮不可重复提交。同一保存请求原样重试不会重复生成版本；下一次主动点击会生成下一个版本。自动保存的修订号独立于文档版本，用于多窗口和多人编辑的冲突检测，不在界面显示。遇到冲突时，先下载草稿，再读取服务器内容并合并。

升级前已产生的历史版本保留，不删除、不重新编号。升级时应让正在编辑的用户先保留草稿，更新后刷新页面；旧编辑器缺少独立修订号，提交时会提示重新读取，避免覆盖新内容。

## 部署

本机 Docker 已由维护者更新。其他环境需一起更新 API、Worker 和前端镜像。

已有业务库可手动执行 `database/v1.0.2.sql`，Docker 和 Kubernetes 交付目录均有同名副本。SQL 仅补充 `wiki_articles.revision` 字段，可重复执行，不包含测试数据，不改动正文或历史版本。新版 API 启动也会自动补充该字段。新装的表结构文件已同步包含它。

不需要新增环境变量、Redis 键或挂载目录。不要重新导入安装文件来更新已有平台。
